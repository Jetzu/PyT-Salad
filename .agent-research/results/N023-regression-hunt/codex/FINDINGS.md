It is already wrong on the first real step; the repeated denoising steps carry that error into a different, more extended structure. `aggressive_fusion` also fails its advertised bit-exact claim, but disabling it does not restore the known-good quality distribution. ## 1. Can the stacked-weight cache serve stale weights? — **CONFIRMED, conditionally; REFUTED as this regression's cause**

Commands: `python cache_probe.py > cache_probe.log` and `python cache_forward.py > cache_forward.log` with the triad Python path above. A hand edit of `.w.data` made `in_sync=False`, with a **0.125** max weight delta. `load_state_dict` restored `True`; `.to(float64)` kept `True`; a second model started `True`; the real checkpoint converter and `FastDenoiser` constructor both left it `True` (`cache_probe.log:1-8`). An edit to a per-block MLP bias after construction changed the sequential pair output by **5.0** but the batched output by **0.0** until `sync()`, after which batched changed by **5.0** (`cache_forward.log:1-4`). Thus a live inference model whose parameters are changed *after* denoiser construction can serve stale weights. No such edit occurs in the tested generator: `scripts/generate.py:666-670` loads through `load_model`, whose `salad_torch/convert/haiku_to_torch.py:199` calls `load_state_dict`; `salad_torch/modules/blocks.py:380-413` registers the post-hook; `salad_torch/modules/fast.py:422-430` syncs once more before compile. `.to(device)` moves registered buffers with parameters, and each new model has its own stack. The buffer creation, sync, and direct buffer reads are at `salad_torch/modules/cond_prologue.py:75-103,174-190`.

## 4. Is `aggressive_fusion` bit-exact? — **REFUTED on the target commit's full fast rollout**

Commands: `sbatch .agent-research/results/N023-regression-hunt/codex/run_aggr603.sbatch` (904773) and `sbatch .../run_aggr603_repeat.sbatch` (904780), on the isolated 603051e source, with `SALAD_OPT_BATCHCOND=0 SALAD_OPT_DETSEG=1`, varying only `SALAD_OPT_AGGRFUSE=0/1`. Fusion therefore changes arithmetic or kernel behavior on this compiled trajectory, despite the commit's bit-exact claim. Thus fusion is a real numerical effect, but it does not explain the severe quality shift. The knob is set at `salad_torch/modules/fast.py:351-356` and documented as bit-exact at `salad_torch/opt.py:92-95`.

## Ranked suspected causes

1. **P7 compiled batched prologue under fast CUDA precision.** Strongest evidence: on the isolated 603051e snapshot, it increases step-0 compiled-versus-eager position error from **0.1418 to 9.7817 Å** with the same input, and the full rollout Rg shifts **13.04 to 17.99 Å**. The source path is `salad_torch/modules/diffusion.py:341-349` into `salad_torch/modules/cond_prologue.py:174-190`. A standalone prologue probe (`sbatch .../run_prologue.sbatch`, 904772) found eager batched versus six sequential branches **0.0** for its fixed inputs, but compiled versus eager **4.56e-04** on zero positions and **5.15e-03** on random positions (`prologue_904772.log:25-27`). Re-running with `PROLOGUE_PRECISION=highest` (`sbatch .../run_prologue_highest.sbatch`, 904778) reduced those compiled gaps to **3.81e-06** and **5.51e-05** (`prohighest_904778.log:25-30`). This localizes a precision-sensitive compilation error to the P7 computation; the exact generated GPU kernel/op responsible was not isolated.
2. **`aggressive_fusion` numerical change, a secondary contributor to design identity.** Strongest evidence: target-commit P7-off deterministic trace **0.006947 Å at step 0 / 11.048 Å at step 200** off versus on, with a same-setting repeat exactly equal. It did not reproduce the Rg quality shift in the n=8 A/B arms.
3. **Stale P7 weight cache after an out-of-band parameter edit, a separate conditional hazard.** Strongest evidence: editing a block bias by **5.0** changed the sequential output by 5.0 and left the batched output at 0.0 change until `sync()`. The standard load-and-sample path was in sync and did not edit parameters after construction.

## Evidence limits

No n=160 A/B sweep was run here; the user's two independent n=160 measurements establish the broader failure rate, while this diagnosis uses n=8 full rollouts and complete deterministic step traces. Cyclic and multi-chain checks were single-forward CPU probes, not full quality rollouts. The exact Inductor/CUDA kernel operation that creates the prologue's compiled discrepancy was not isolated by kernel-level tracing; the evidence localizes it to P7 plus compilation and shows strong dependence on `high` versus `highest` matmul precision. The default `tests/test_design_quality.py` checkpoint path (`params/default_vp-200k.jax`) is not loadable by `load_param_npz`; all successful jobs passed the existing NPZ path explicitly. No training run, source patch, commit, stage, push, or PR was performed.
